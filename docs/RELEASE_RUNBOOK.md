## 1. Observability & Log Correlation Protocol

### A. Trace Context Standards
Every incoming request, background action, durable worker execution, and receipt must bind to a shared `TraceContext`:
- `traceId`: Root correlation identifier originating at client intake or API boundary.
- `requestId`: HTTP request identifier generated by the edge gateway.
- `actionId`: Human-governed action identifier in `actionQueueStore`.
- `jobId`: Durable queue run identifier in `durableJobQueue`.
- `receiptHash`: Cryptographic SHA-256 digest minted upon execution.

### B. Secret Sanitization Mandate
All log emitters must pass structured metadata through `sanitizeSecrets`. The following patterns are automatically stripped:
- Bearer tokens: `Bearer [A-Za-z0-9_\-\.]{15,}` -> `Bearer [REDACTED:BearerToken]`
- LLM Provider keys: `sk-[A-Za-z0-9_\-]{20,}` -> `[REDACTED:AiKey]`
- OAuth access tokens: `ya29\.[A-Za-z0-9_\-]{20,}` -> `[REDACTED:OAuthToken]`
- Database credentials: `postgres://...` -> `postgres://[REDACTED_CREDENTIALS]@[HOST]`
- Private keys: `-----BEGIN PRIVATE KEY-----` -> `[REDACTED:PrivateKey]`
- Sensitive property names (`password`, `secret`, `apiKey`, `token`, `credentials`) are replaced with `[REDACTED:SensitiveKey]`.

## 2. Disaster Recovery: Backup & Restoration

### A. Workspace Backup Generation
1. Workspace backups capture tenant configuration, action histories, verified learnings, and second brain document graphs.
2. The payload is serialized deterministically and hashed via SHA-256:
   ```bash
   node -e "import('./dist/server.js').then(m => m.createBackup('ws-client-alpha'))"
   ```
3. Backup snapshots are stored in an encrypted tenant enclave with immutable timestamps.

### B. Workspace Restoration Procedure
1. Verify the payload checksum matches the recorded metadata.
2. If checksum fails, abort restore immediately to prevent state corruption.
3. Apply restored records within a single database transaction.

## 3. Worker Failure Recovery & Dead-Letter Handling

### A. Leased Execution Lifecycle
1. Worker claims next job and acquires a 30-second distributed lease (`lockedUntil = now + 30s`).
2. Worker emits heartbeats every 5 seconds while processing.
3. If a worker crashes mid-execution, the lease expires.

### B. Orphaned Job Reconciliation
1. The supervisor identifies jobs where `status === 'running'` and `lockedUntil <= now`.
2. The job transitions to `reconciling` rather than blind re-execution.
3. The reconciliation worker verifies upstream transaction state (e.g., Stripe charge ID, Ad network campaign ID).
4. If external side-effects succeeded, the job is marked `succeeded` and a receipt is minted.
5. If side-effects failed, the job retry count is incremented up to `maxRetries` (default: 3).
6. Jobs exceeding max retries move to `dead_letter` for operator inspection.

## 4. Emergency Deployment Rollback Runbook

### A. Rollback Trigger Criteria
A rollback must be initiated under any of the following conditions:
- Canary deployment error rate exceeds 0.5% over a 5-minute rolling window.
- Unhandled P0/P1 defect discovered impacting multi-tenant isolation.
- Secret vault boundary detection alarm triggers.
- External connector OAuth failure rate spikes above 5%.

### B. Execution Steps
1. **Authorize Rollback**: Principal Lead (Nazim) approves the rollback target SHA.
2. **Shift Traffic**: Edge proxy points immediately to previous stable SHA.
3. **Invalidate Runtime Caches**: Flush stale route caches and active session allocations.
4. **Log Audit Trail**: Record `DEPLOYMENT_ROLLBACK_EXECUTED` event in the immutable governance ledger.

## 6. Runtime Limits & System Readiness Thresholds

| Parameter | Limit | Failure Action |
| :--- | :--- | :--- |
| Worker Default Timeout | 300 seconds | Abort job and mark for reconciliation |
| Worker Maximum Timeout | 1,800 seconds (30m) | Hard SIGTERM process termination |
| Max Request Body Size | 10 MB | HTTP 413 Payload Too Large |
| Max Artifact Bundle Size | 50 MB | Stream download error |
| Max Process Memory | 2,048 MB | Readiness probe transitions to `degraded` |
| Max Concurrent Jobs / Tenant | 5 jobs | Queue subsequent jobs with backoff |

### Readiness Endpoint Verification
- `/healthz` and `/api/health`: Return HTTP 200 and process uptime.
- `/readyz` and `/api/ready`: Inspect database connectivity, worker heartbeat freshness (<30s), and vault boundary status.
