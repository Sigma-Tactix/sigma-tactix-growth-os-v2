# Paid client work: three delivery contracts

These are proposed service workflows, not existing completed product capabilities or guaranteed financial results. Agree scope and acceptance with the client. Use only relevant capabilities; a client does not need every suite on every job.

| Job | Required input | Capability sequence | Client deliverable | What accepted means |
| --- | --- | --- | --- | --- |
| Growth diagnostic and action plan | Confirmed business goal, audience/offer, permitted website/data, period and constraints | Intake -> source/website review -> diagnostics + relevant search/competitor analysis -> evidence review -> prioritized recommendations | Branded diagnostic PDF, decision deck, prioritized action/measurement workbook | Sources resolve; unsupported findings remain unknown; top three recommendations have rationale, owner, effort and success measure; files open correctly; client acknowledges the agreed next action |
| Campaign delivery package | Approved objective, audience, offer, channel, budget constraints, brand references and success measure | Brief -> focused research -> plan -> required copy/image/video/landing assets -> preview/approval -> verified publication or explicit export/handoff -> tracking checks | Approved media plan and assets; landing/copy package; execution receipts when publishing is in scope | Assets match brief and version approved; budgets/UTMs/destinations checked; actual files usable; authorized delivery has receipt; export-only scope is declared before delivery, never disguised as publication |
| Recurring performance and improvement | Verified source accounts, metric/attribution definitions, prior actions, reporting window and agreed review cadence | Source refresh -> reconciliation -> compare -> explain -> review recommended changes -> execute approved work -> next measurement -> approved lesson | Executive PDF, editable PPTX, working XLSX, action/result ledger and next-period plan | Totals reconcile to agreed sources; dates/currency/limitations visible; actions link to evidence/results; measured impact separated from estimates; exports pass quality review; client has a decision-ready summary |

## Capability relevance

- Diagnostics, evidence/Knowledge Vaults, planning, approvals and reporting form the common delivery foundation.
- Creative, SEO/CRO, paid media, social and lifecycle are specialist capabilities used when the agreed client objective calls for them. Share the brief and evidence rather than reproducing setup per module.
- Inbound/outbound needs an actual acquisition service and authorized destinations. Do not add outreach to a reporting job because the module exists.
- Attribution must state what can actually be measured. Blended CAC, channel ROAS and incrementality are different questions.
- Market simulation is optional research with explicit assumptions. It must not imply knowledge of competitor spend or reliable prediction without evidence.
- Agent cockpit, model configuration, routing, worker topology and test harnesses belong primarily to operators. Client-facing agent progress should describe real work and results in ordinary language.
- The 3D knowledge view is optional exploration. It is not a prerequisite for receiving a report or approving an asset.

## Work order for any client job

Goal and scope -> milestone/output -> prerequisite task graph -> one task owner/lease -> action and expected artifact -> acceptance criteria -> evidence -> client review -> approved lesson.

Use the same authoritative records for human screens and agent tools. An agent cannot count a generated plan as a delivered campaign, a scheduled job as a published post, or an executed task as proven revenue impact.
